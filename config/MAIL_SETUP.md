# Настройка почты GramPay на Reg.ru

Отправщик раньше всегда выполнял STARTTLS. Теперь режим подключения задаётся явно:
`none` — без шифрования, `tls` — STARTTLS, `ssl` — TLS с момента подключения.
Настройки из запроса пользователя: `mail.hosting.reg.ru`, порт `587`, режим `none`,
логин и отправитель `admin@grampay.net`. Пароль в репозитории отсутствует.

1. Загрузите обновлённый `email_service.php` на PHP-хостинг.
2. Скопируйте `config/mail.example.php` на один каталог выше корня сайта под именем
   `grampay-mail.php`. Например, для `/var/www/account/data/www/grampay.net/`
   файл должен находиться в `/var/www/account/data/www/grampay-mail.php`.
3. Укажите пароль ящика в поле `GRAMPAY_SMTP_PASS`. Ограничьте чтение файла
   владельцем PHP-процесса (например, права 600). Не размещайте файл в доступном по HTTP каталоге.
4. Если этот путь занят или неудобен, задайте переменную окружения `GRAMPAY_MAIL_CONFIG`
   с абсолютным путём к закрытому PHP-файлу, возвращающему такой же массив.
   Любой параметр `GRAMPAY_SMTP_*` можно задать непосредственно в окружении PHP.
5. Выполните `php tools/check-mail.php --to=YOUR_EMAIL` на хостинге.
   Успех означает принятие SMTP-сервером, а не гарантированное попадание во входящие.

Приоритет настроек: переменные окружения → закрытый PHP-файл → существующий `.env` → значения по умолчанию.
Старый `.env` по-прежнему поддерживается. Apache блокирует его выдачу через `.htaccess`;
для Nginx нужен запрет в конфигурации сервера или перенос настроек за пределы корня сайта.
`configuration.php` Joomla не управляет отправкой писем собственного приложения GramPay.

## Диагностика

В PHP error_log записывается этап и код SMTP, без пароля и текста письма:

- `configuration`: не указан пароль, некорректный отправитель или режим подключения.
- `connect`: нет соединения, неверный порт или недоступен сервер.
- `STARTTLS`: сервер не поддерживает выбранный TLS-режим или проблема сертификата.
- `authentication`, код 535: проверьте логин и пароль ящика.
- `sender` / `recipient`: отклонён отправитель или получатель.
- `message acceptance`: сервер не принял содержимое письма.

Режим `none` передаёт авторизацию без транспортного шифрования. Если нужен шифрованный
режим Reg.ru, задайте `ssl` и порт `465`. Проверка TLS-сертификата включена;
при ошибке TLS автоматического перехода к нешифрованной отправке нет.
